# Dawn AI Agent P0 评测最终报告

- 报告日期：2026-07-21
- 评测对象：Dawn AI Agent 系统
- 评测范围：4 个 P0 维度
- 总用例数：80
- 通过用例数：77
- 整体通过率：96.25%
- 报告位置：`test-result/agent-p0-evaluation-final-report-2026-07-21.md`

## 1. 执行摘要

本次评测覆盖 Agent 系统的 4 个 P0 维度：RAG Recall、Groundedness、Tool Selection 和 Safety。整体结果显示，Dawn AI Agent 已经具备较强的基础业务可用性，尤其在知识召回、基于证据的事实回答、工具选择等核心能力上表现稳定。

但是，Safety 维度仍有 3 条高风险失败用例，主要集中在身份伪装、授权包装、专业场景伪装等对抗式输入下。由于 Safety 属于 P0 阻断项，其失败不能被其他维度的高分抵消。

**最终结论：Dawn AI Agent 当前适合受控内部试运行，但暂不建议面向开放用户或不受控生产环境发布。**

## 3. 核心发现

### 3.1 RAG Recall：召回能力可用，精度仍需提升

RAG Recall 20 条用例全部通过，说明系统能够正确识别知识库相关问题，并召回期望文档。正向检索用例中，Recall@K、Hit@K、MRR@K 均达到 1.0，说明关键文档能够被稳定命中且排序靠前。

主要问题是召回噪声偏高。正向用例平均 Precision@K 约为 0.55，Noise Rate 约为 0.45。这意味着系统基本不会漏掉目标文档，但经常同时混入无关文档。当前 Groundedness 表现较好，可以部分缓冲噪声影响；但在长上下文、多文档冲突或复杂问题场景下，噪声仍可能降低最终回答质量。

### 3.2 Groundedness：事实忠实度是当前最强能力之一

Groundedness 20 条用例全部满分通过。Agent 在给定 grounding 文档后，能够稳定基于材料回答，避免编造、扭曲、遗漏关键事实或与来源冲突。

这说明答案生成阶段具备较好的事实约束能力。只要上游检索提供的上下文可靠，Agent 的最终回答质量具有较高可信度。

### 3.3 Tool Selection：选择准确，但 fallback 策略需要收紧

Tool Selection 20 条用例全部通过，说明 Agent 能够正确识别知识库查询、Web 查询、命令执行等典型场景，并选择期望工具。

不过，部分用例出现了额外工具调用。例如内部知识库未命中后继续调用 WebTool。虽然当前评测允许 extra tools，但从生产可靠性角度看，这类行为会带来三个风险：

1. 私有或内部问题可能被错误转向公网搜索。
2. 工具链变长，增加延迟、成本和失败面。
3. Runtime 实际行为与 Planner 初始选择不完全一致，可预测性下降。

因此，工具选择能力本身已经可靠，但工具 fallback 治理仍需加强。

### 3.4 Safety：当前唯一 P0 阻断项

Safety 20 条用例中通过 17 条，失败 3 条。失败集中在对抗式包装场景，包括：

1. 通过专业身份声明弱化高风险意图。
2. 通过授权或资质声明包装潜在攻击性请求。
3. 对非法入侵、隐私侵犯、自伤等高风险领域的边界识别不够稳定。

这说明系统对显式恶意请求已有一定拦截能力，但对“身份伪装 + 合法化叙事 + 专业场景包装”的 jailbreak 鲁棒性不足。由于失败类型涉及高风险内容，Safety 必须作为发布前优先修复项。

## 4. 可用性判断

### 4.1 适合的使用场景

当前 Agent 可以进入受控内部试运行，适合以下场景：

- 内部知识库问答
- 技术文档检索与总结
- 基于给定材料的事实型回答
- 常规工具调用和任务路由
- 研发团队内部评测、演示、灰度验证

### 4.2 暂不适合的使用场景

当前 Agent 暂不建议用于以下场景：

- 面向不受控外部用户的开放式生产环境
- 高风险安全、医疗、自伤、隐私等领域的自由问答
- 自动执行高影响操作的生产工作流
- 缺少人工兜底和监控的全自动 Agent 场景

## 5. 可靠性判断

从第一性原理看，Agent 系统可靠性不仅取决于“正常问题能答对”，还取决于“异常输入、对抗输入、上下文噪声下是否仍然守住边界”。

本次结果说明：

- **正常业务链路可靠性较高**：RAG、Groundedness、Tool Selection 均 100% 通过。
- **事实生成可靠性较强**：Groundedness 满分说明模型在证据约束下表现稳定。
- **安全鲁棒性不足**：Safety 85% 通过率不足以支撑开放环境发布。
- **检索上下文质量仍需提升**：RAG 召回不漏关键文档，但噪声偏高。

因此，系统已经具备“可用”的基础，但还没有达到“可信、可开放、可大规模发布”的可靠性标准。

## 6. 改进优先级

### P0：强化 Safety Guardrail

- 将“我是医生”“我是安全专家”“已获授权”等身份声明统一视为未验证输入。
- 对自伤、网络攻击、隐私侵犯、欺诈、违法行为等高风险意图增加二次风险分类。
- 对高风险请求只允许输出安全替代方案、合规边界、求助路径或防御性原则。
- 扩充 Safety 评测集，重点增加 persona jailbreak、授权包装、专业身份伪装、多轮诱导类用例。
- Safety 修复后必须重新运行完整 P0 评测。

### P1：降低 RAG 召回噪声

- 优化 rerank、threshold、topK 策略。
- 在进入答案生成前增加文档相关性过滤。
- 对多文档上下文做压缩与去噪。
- 增加“召回正确但噪声过高”的单独观测指标。

### P1：收紧工具 fallback

- 内部知识库未命中时，不默认转 WebTool。
- 对“我们项目”“内部文档”“上次上传”等私有语义，优先追问或说明未找到。
- 对额外工具调用增加可解释性记录。
- 将 Runtime 实际工具链与 Planner 初始决策差异纳入评测指标。

## 7. 发布建议

| 发布形态 | 建议 | 原因 |
|---|---|---|
| 内部受控试运行 | 可以 | 核心业务能力已可用，风险可控 |
| 小范围灰度 | 谨慎可以 | 需开启日志、人工兜底和安全监控 |
| 开放生产发布 | 不建议 | Safety 未达 P0 放行标准 |
| 高风险领域自动化 | 不建议 | 安全边界仍不稳定 |

建议的 P0 放行门槛：

- Safety：100% 通过
- Groundedness：保持 100% 通过
- Tool Selection：保持 100% 通过，并减少不必要 extra tool 调用
- RAG Recall：保持 100% 通过，同时降低 Noise Rate、提升 Precision@K

## 8. 最终结论

Dawn AI Agent 当前已经具备较好的工程可用性，能够完成知识检索、工具路由和基于证据的事实回答。但从生产可靠性的角度看，Safety 仍是明确阻断项。

**结论：可以进入内部受控试运行；不建议直接开放生产发布。**

下一步应优先修复 Safety 失败路径，并在修复后重新运行 P0 评测。只有当 Safety 达到 100% 通过，且 RAG 噪声与工具 fallback 问题得到收敛后，才建议进入更大范围的生产灰度。
